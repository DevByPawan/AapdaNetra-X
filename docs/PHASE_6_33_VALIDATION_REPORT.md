## 4. Scientific Claims, Provenance & Human-in-the-Loop Safeguards



### A. Real-Data Provenance Audit

* **Dataset**: Real historical Yamuna River flood dataset (`Yamuna_2025.pdf`, July 2025 Delhi flood event).

* **Ingestion & Alignment**: Real-data preprocessors extract CWC Hathnikund discharge rates, Yamuna Old Railway Bridge water levels, Delhi Traffic Police road closure advisories, and IMD rainfall intensity. Preprocessing pipeline (`test_phase6_22_3` through `test_phase6_23`) handles missing value imputation, trend computation, and temporal alignment cleanly.



### B. Multi-Hazard Safeguards

* **Unsupported Hazard Protection**: Requesting decision recommendations for non-flood hazards (e.g., `earthquake`, `landslide`, `cyclone`) cleanly returns `decision_support_available: False` with an explicit disclaimer (`UNSUPPORTED_HAZARD: No operational ML model for specified hazard type`). The system never falls back to flood risk formulas for unsupported hazards.



### C. Human-in-the-Loop (HITL) Decision Controls

* **Recommendation Lifecycle**: Decision recommendations generated by `compute_emergency_decision` remain in state `RECOMMENDED` until explicitly acted upon by an authorized human operator.

* **RBAC & Accountability**: Approvals (`/api/decision/approve`) and Rejections (`/api/decision/reject`) enforce Role-Based Access Control (`responder` or `admin` role required) and audit log responder IDs, timestamps, and justifications.



### D. Security Hardening

* **Authentication & Authorization**: Protected endpoints require valid Bearer tokens or API keys when `auth_enabled=True`.

* **CORS & Input Validation**: Strict CORS white-listing prevents unauthorized cross-origin access. Payload size capping (1MB max) and input range validation block buffer overflow and non-finite value attacks.

* **Rate Limiting & Error Sanitization**: IP-based sliding window rate limiter returns HTTP 429 when limits are exceeded. API error responses sanitize file paths (`/Users/...`), database connection strings (`postgresql://`), and stack traces.

## 5. Known Limitations & Unresolved Issues



1. **PostGIS Live Service**: PostGIS spatial database tests (64 tests) were not run against a live PostgreSQL/PostGIS database. Live spatial queries remain unverified until a PostGIS service is online.

2. **SSE Streaming Test Client Mechanics**: In FastAPI TestClient, infinite SSE stream endpoints require using `client.stream("GET", ...)` context managers and explicit matching for the `"testclient"` IP host key in `broker._ip_subscribers` to prevent client thread blocking.

3. **External API Fallbacks**: Live data providers gracefully degrade to cached or simulated baselines when external API keys or endpoints are unreachable, setting `enable_fallback=True`.
