## 2. 7-Feature Risk Engine Pipeline

The core intelligence engine transforms 7 physical parameters into risk predictions:

1. `rainfall_intensity` (mm/h)
2. `rainfall_trend` (mm/h²)
3. `water_level` (m above datum)
4. `water_level_trend` (m/h)
5. `road_congestion` (ratio $0.0 - 1.0$)
6. `population_exposure` (headcount)
7. `infrastructure_vulnerability` (ratio $0.0 - 1.0$)

```mermaid
graph TD
    A["1. Real-Data / Live / Simulated Ingestion<br/>(Yamuna 2025 CWC / IMD / Simulated)"] --> B["2. Validation & Range Clipping<br/>(ml.features.validate_and_clean_features)"]
    B --> C["3. Gradient Boosting Regression<br/>(scikit-learn GBR Artifact)"]
    C --> D["4. Emergency Risk Classification<br/>(LOW < 30 | MODERATE < 60 | HIGH < 85 | CRITICAL <= 100)"]
    D --> E["5. Local SHAP Attribution<br/>(shap.TreeExplainer Feature Contributions)"]
    E --> F["6. Risk-Aware Network Routing<br/>(NetworkX Dijkstra Traversal Cost)"]
    F --> G["7. HITL Decision Support<br/>(Plan Recommendation & Operator Verification)"]
    G --> H["8. SSE Stream & Dashboard Rendering<br/>(FastAPI SSE & React 19 UI)"]
```

## 3. Human-in-the-Loop (HITL) Emergency Decision Lifecycle

Emergency decision recommendations generated by `compute_emergency_decision` require explicit operator verification:

```mermaid
stateDiagram-v2
    [*] --> RECOMMENDED: System Computes Decision Recommendation
    RECOMMENDED --> APPROVED: Human Operator Grants Approval (/api/decision/approve)
    RECOMMENDED --> REJECTED: Human Operator Rejects Recommendation (/api/decision/reject)
    RECOMMENDED --> REVISED: Counterfactual Scenario Executed
    REVISED --> RECOMMENDED: Updated Recommendation Generated
    APPROVED --> [*]: Audit Trail Saved to Persistence
    REJECTED --> [*]: Audit Trail Saved to Persistence
```

## 4. Multi-Hazard Capability Matrix & Unsupported-Hazard Safeguards

AapdaNetra-X enforces a strict multi-hazard capability guardrail:

| Hazard Type | Model Status | Operational Endpoint | Behavior / Disclaimer |
| :--- | :--- | :--- | :--- |
| **Riverine Flood** | Operational | `/api/risk`, `/api/decision` | Returns GBR ML risk, SHAP attributions, and evacuation paths. |
| **Flash Flood** | Operational (Hybrid) | `/api/risk`, `/api/simulation` | Evaluates rapid rainfall escalation rates (`rainfall_trend`). |
| **Earthquake** | Unsupported | `/api/decision/recommend` | Returns `decision_support_available: False`, disclaimer `UNSUPPORTED_HAZARD`. |
| **Landslide** | Unsupported | `/api/decision/recommend` | Returns `decision_support_available: False`, disclaimer `UNSUPPORTED_HAZARD`. |
| **Cyclone** | Unsupported | `/api/decision/recommend` | Returns `decision_support_available: False`, disclaimer `UNSUPPORTED_HAZARD`. |

## 5. Security Architecture & Rate Limiting

1. **Authentication**: Optional/Enforced Bearer Token and `X-API-Key` headers evaluated via `app.core.security`.
2. **Role-Based Access Control (RBAC)**: State-changing decision endpoints (`/api/decision/approve`, `/api/decision/reject`) require `responder` or `admin` role token.
3. **CORS Hardening**: Strict origin white-listing (`settings.cors_origins`). Capped request body sizes ($1\text{ MB}$ max).
4. **Rate Limiting**: Sliding window IP rate limiter returning HTTP 429 when threshold exceeded.
5. **SSE Connection Bounds**: Maximum subscriber limits per IP (`max_sse_subscriptions_per_ip = 2`).
6. **Error Response Sanitization**: Suppresses stack traces, database strings, and filesystem paths in 4xx/5xx API responses.
